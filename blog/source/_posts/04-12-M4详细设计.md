## 二、优雅退出（Graceful Shutdown）

### 以前的问题

```go
r.Run(addr)   // 阻塞
// 进程被 SIGINT/SIGTERM 杀掉时：
// 1. 处理中的请求直接被切断，客户端看到连接重置
// 2. WebSocket 没发 Close 帧，客户端要等心跳超时才感知
// 3. DB/Redis 连接没释放
```

### 现在的做法

```go
srv := &http.Server{Addr: ..., Handler: router.NewRouter()}
go srv.ListenAndServe()

quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit

// 1. 停止接收新请求，等待处理中的请求完成（最多 10s）
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
srv.Shutdown(ctx)

// 2. 主动断开所有 WebSocket
ws.DefaultHub.CloseAll()

// 3. 释放 DB / Redis
core.CloseBaseServices()
```

### 为什么顺序是「先 HTTP 后 WS 后 DB」

- 先关 HTTP：不再接新请求，等在途请求处理完
- 再关 WS：客户端立即收到 Close 帧，触发重连
- 最后关 DB/Redis：保证前面的清理逻辑还能用数据库

**面试点**：优雅退出要做哪些事？顺序为什么重要？

## 三、限流（滑动窗口）

### 为什么需要

- **登录接口**：可被撞库（批量试密码）
- **注册接口**：可被批量注册垃圾账号
- **搜索接口**：可被批量扫用户

### 实现：内存滑动窗口

```go
type rateLimiter struct {
    mu     sync.Mutex
    hits   map[string][]time.Time   // key(IP) -> 请求时间列表
    limit  int
    window time.Duration
}
```

每次请求：
1. 清理该 key 里超出窗口的旧记录（**懒清理**，不用后台 goroutine）
2. 判断是否超限
3. 未超限则记录本次

### 为什么用滑动窗口而不是固定窗口

固定窗口在边界会翻倍：
```
59s 发 10 次 + 60s 发 10 次 = 1 秒内 20 次（虽然每分钟限 10）
```
滑动窗口只统计「最近 60 秒」，边界平滑。

### 当前配置

| 接口 | 限制 |
|---|---|
| `/register`、`/login` | 20 次/分钟/IP |
| `/users/search` | 30 次/分钟/IP |
| `/token/refresh` | 不限（客户端正常刷新频率） |

### 局限与后续

**单机内存**：多实例部署时每个实例独立计数，总量会翻倍。
生产解法：Redis（`INCR` + `EXPIRE`，或 Lua 脚本做滑动窗口）。M6 拆微服务时升级。

**实测**：连续登录 25 次 → 前 20 次 401，后 5 次 429。

## 四、WebSocket 并发安全

### Hub 的三个并发场景

1. **注册/注销**：连接建立/断开（写锁）
2. **推送**：消息发送（读锁）
3. **遍历**：`SendToUser` 复制连接列表后释放锁

### 关键代码

```go
func (h *Hub) SendToUser(userID uint64, payload []byte) bool {
    h.mu.RLock()
    conns := h.clients[userID]
    list := make([]*Client, 0, len(conns))   // 复制！
    for c := range conns { list = append(list, c) }
    h.mu.RUnlock()                            // 释放锁后再做 IO

    for _, c := range list { c.Enqueue(payload) }
    return len(list) > 0
}
```

**为什么先复制再释放锁**：持锁期间做 channel 操作/网络 IO 会阻塞其他 goroutine，放大锁竞争。

### 并发测试

```go
// 200 个 goroutine 同时注册/推送/注销
func TestHubConcurrentRegisterSendUnregister(t *testing.T) { ... }
```

运行：
```bash
go test ./internal/ws/ -race -count=1
```

> **注意**：`-race` 需要 cgo + gcc。本机没装 gcc 时只能跑普通测试。
> 安装 MinGW/TDM-GCC 后即可用 `-race` 检测数据竞争。
> 在 Linux/macOS 上 `-race` 开箱即用。

## 五、消息扇出的并发控制

### 问题

群成员 200 人时，`PushMessage` 如果无脑起 200 个 goroutine：
- goroutine 数量瞬间暴涨
- 对 Hub 锁、网络造成瞬时压力

### 方案：信号量限制并发数

```go
const pushConcurrency = 16
var pushSem = make(chan struct{}, pushConcurrency)

for _, uid := range memberIDs {
    wg.Add(1)
    pushSem <- struct{}{}          // 获取令牌（满了就阻塞等待）
    go func(uid uint64) {
        defer wg.Done()
        defer func() { <-pushSem }()  // 释放令牌
        DefaultHub.SendToUser(uid, frame)
    }(uid)
}
wg.Wait()
```

小会话（≤10 人）直接顺序推送，避免 goroutine 开销。

**面试点**：如何控制并发数？三种方式——
- 带缓冲 channel 当信号量（本项目）
- `golang.org/x/sync/semaphore`（加权信号量）
- worker pool

## 六、goroutine 泄漏排查

### 常见泄漏点

| 泄漏点 | 原因 |
|---|---|
| 启动 goroutine 后没人关 | 例如 `for { <-ch }` 但 ch 永远不关闭 |
| 阻塞在 channel 发送 | 消费者已退出，生产者阻塞 |
| 阻塞在网络 IO | 连接没设超时 |
| 定时器没 Stop | `time.NewTicker` 忘了 `Stop()` |

### 本项目怎么防

- `WritePump` 里 `defer ticker.Stop()`
- `Client.Close()` 用 `sync.Once` 保证幂等
- `Enqueue` 队列满 → 主动断开慢连接
- 优雅退出时 `CloseAll()` 清空所有连接（每个连接的读写 goroutine 都会随 conn 关闭而退出）

### 排查工具

```bash
go test -race                       # 数据竞争
go tool pprof http://localhost:6060/debug/pprof/goroutine  # goroutine 数
```
（本项目暂未挂 pprof，M6 可加）

## 七、初始化错误处理改进

**以前**：
```go
if err != nil {
    fmt.Print(...)
    os.Exit(0)   // ❌ 退出码 0 = 成功；且跳过 defer
}
```

**现在**：
```go
func InitBaseServices() error {
    if _, err := db.LoadMysql(); err != nil {
        return fmt.Errorf("数据库连接失败: %w", err)
    }
    ...
}
// main:
if err := core.InitBaseServices(); err != nil {
    log.Fatalf(...)   // 退出码 1
}
```

**顺手修掉的安全问题**：以前 `main` 里有 `fmt.Println("Config：", global.Config)`，
会把数据库密码、JWT secret **打印到日志**。已删除。

> 面试点：日志里绝对不能打印密码/token/密钥。

## 十、注意点清单

1. **优雅退出顺序**：HTTP → WS → DB/Redis
2. **`Shutdown` 要设超时**，否则可能永远等
3. **限流单机内存**，多实例要 Redis
4. **滑动窗口**优于固定窗口（边界突发）
5. **限流 key 用 IP**，但注意代理场景要取真实 IP（`X-Forwarded-For`）
6. **Hub 持锁时不做 IO**，先复制数据
7. **信号量控制并发**：`pushSem <- struct{}{}` / `<-pushSem`
8. **`-race` 需要 cgo**，Linux/macOS 开箱即用，Windows 要装 gcc
9. **日志不打印密码/token**
10. **每个 goroutine 都要有退出路径**（连接关闭、channel 关闭、ctx 取消）
