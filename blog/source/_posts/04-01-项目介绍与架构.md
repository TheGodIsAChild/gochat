## 为什么做这个项目

我想系统练习三件事：**并发编程、微服务拆分、消息队列**。普通的 CRUD 项目练不到这些，
于是决定做一个「仿微信」的即时通讯后端：

- 有长连接（WebSocket）→ 练并发
- 有多个业务域（用户/好友/聊天/群/通话）→ 练拆分
- 有异步推送需求 → 练消息队列

## 技术栈

| 层 | 技术 |
|---|---|
| Web 框架 | Gin |
| ORM | GORM + MySQL 8 |
| 缓存 | Redis |
| 鉴权 | JWT 双 token |
| 实时通信 | gorilla/websocket |
| 语音 | WebRTC（信令服务） |
| 微服务 | gRPC |
| 消息队列 | RabbitMQ |
| 前端 | 原生 HTML/CSS/JS（仿微信三栏） |

## 架构演进：先单体，再微服务

```
M0–M5：单体
  客户端 ──HTTP/WS──► 单体服务 ──► MySQL / Redis

M6–M7：拆分
  客户端 ──HTTP──► gateway ──gRPC──► user 服务 / chat 服务
                        │
                        └──► RabbitMQ ──► 异步推送
```

**为什么先单体**：只有先体会单体的痛点（扩缩容、故障隔离、部署耦合），才知道为什么要拆。

## 里程碑

| 里程碑 | 内容 |
|---|---|
| M0 | 脚手架、配置、健康检查 |
| M1 | 注册/登录（双 token）、资料、好友（申请/事务/黑名单） |
| M2 | 会话、消息幂等、WebSocket、离线消息 |
| M3 | 群聊（建群事务、成员管理、权限） |
| M4 | 并发加固（优雅退出、限流、并发安全） |
| M5 | WebRTC 语音通话（信令转发） |
| M6 | gRPC 微服务 + gateway |
| M7 | RabbitMQ + 本地消息表（最终一致性） |
