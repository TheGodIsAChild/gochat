> 这篇是把「小白读这个项目时**真正会卡住的问题**」收集起来逐条回答的。
> **卡住时先来这儿搜一下关键词**，大部分问题都能直接解决。

## A. 刚开始（8 问）

### A1. 我只会 Go 语法，能看懂这个项目吗？

**能，但要按顺序看**。直接打开 `main.go` 会懵，因为里面全是没见过的包（gin、gorm、yaml）。
建议顺序：`01-03 环境准备` → 跑通 → `01-04 一次 HTTP 请求` → `01-05 代码地图` → 里程碑。

### A2. 需要多久？

- **跑通 + 看懂主链路**：3 天（每天 1.5 小时）
- **理解所有模块**：2 周
- **能改功能 + 面试**：3 周

### A3. Docker 是什么？不装行不行？

Docker 是「装软件的容器」，用来跑 MySQL/Redis/RabbitMQ，一条命令起三个服务，卸载干净。
**不装不行**——除非你愿意在本机手动装 MySQL+Redis+RabbitMQ（更麻烦，且容易和已有环境冲突）。

装 Docker Desktop 后，命令行执行 `docker version` 能看到版本就说明装好了。

### A4. 项目代码在哪？怎么用 VS Code 打开？

```
你的项目目录/
└── gochat/          ← 用 VS Code 打开这个文件夹
    ├── main.go
    ├── config.yaml
    ├── docker-compose.yml
    ├── internal/
    └── ...
```

VS Code 里 `文件 → 打开文件夹 → 选 gochat`。装 Go 插件后会自动提示装工具。

### A5. `go run .` 后面那个点是什么意思？

`.` 表示「当前目录」。`go run .` = 编译并运行当前目录下的 `main` 包。
对比：`go run main.go` 只编译这一个文件（如果 main.go 引用了同目录其他文件会报错）。

### A6. 依赖下载很慢 / 一直失败怎么办？

国内网络必须配代理（**这是新手第一个大坑**）：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GOFLAGS=-mod=mod
```

然后再 `go run .`。如果卡在 `verifying`，可以加：

```bash
go env -w GOSUMDB=off
```

> 本项目的 `go.sum` 已提交，正常情况下 `go run .` 会自动下载依赖。

### A7. 我可以只读文章、不跑项目吗？

**不行**。这个项目 80% 的知识点（事务回滚、幂等冲突、WebSocket 推送）**只能在运行中理解**。
不跑的话，你只能背结论，面试一追问细节就答不上来。

### A8. 报错了完全看不懂怎么办？

按这个顺序：

1. **只看错误的第一行**（后面是调用栈，越看越晕）
2. 复制错误信息去 [踩坑集](/blog/2026/11/14/01-06-踩坑集/) 搜
3. 用 `go build ./...` 单独编译（能区分是编译错误还是运行时错误）
4. 打开报错的文件和行号，看那行前后 20 行
5. 打印变量：`log.Printf("debug: %+v", x)`

## B. 跑项目（8 问）

### B1. 怎么确认三个容器都起来了？

```bash
docker ps
```

要看到 **STATUS 是 `Up ... (healthy)`**：

```
gochat-mysql       Up 2 minutes (healthy)
gochat-redis       Up 2 minutes (healthy)
gochat-rabbitmq    Up 2 minutes (healthy)
```

如果显示 `Restarting` 或 `Exited`：`docker logs gochat-mysql --tail 50` 看原因。

### B2. 端口 8080 被占用怎么办？

Windows 查谁占用了：

```powershell
netstat -ano | findstr :8080
tasklist | findstr <上一步查到的PID>
```

解决：杀掉进程，或改 `config.yaml` 里的 `server.addr: ":9090"`。

### B3. 浏览器打不开 `127.0.0.1:8080` 怎么办？

按顺序查：

1. 服务端控制台有没有打印 `HTTP 服务启动: :8080`（没有就是没起来）
2. 是不是用 `https://` 打开了？要 `http://`
3. 换 `localhost:8080` 试试（有时 hosts 解析问题）
4. F12 → Console 看有没有报错

### B4. `-db` 参数是干嘛的？不传会怎样？

`-db` = 启动时执行 `AutoMigrate`（自动建表）。
不传的话，如果数据库是空的，服务能起来但**一操作就报「表不存在」**。

第一次跑必须带 `-db`，之后可以不带。

### B5. 想直接看/改数据库怎么办？

```bash
# 进 MySQL 命令行
docker exec -it gochat-mysql mysql -uroot -proot gochat

# 常用命令
SHOW TABLES;                                    -- 看所有表
SELECT id,username,nickname FROM users;         -- 看用户
SELECT * FROM messages ORDER BY id DESC LIMIT 5; -- 看最近消息
```

> 注意：容器里的 MySQL 用户是 `gochat/gochat123`，root 密码是 `root`。

### B6. 数据库搞乱了怎么重置？

```bash
# 停掉并删除数据卷（数据会全部丢失！）
docker compose down -v

# 重新起
docker compose up -d

# 重新建表
go run . -db

# 生成演示数据
powershell -ExecutionPolicy Bypass -File .\scripts\seed-demo.ps1
```

### B7. 怎么模拟两个用户聊天？

1. 普通窗口打开 `http://127.0.0.1:8080/`，登录 alice
2. 开一个**无痕窗口**（Chrome: `Ctrl+Shift+N`），登录 bob
3. 两个窗口各自加好友、发消息

> 为什么要无痕窗口？因为普通窗口共用 localStorage，token 会互相覆盖。

### B8. 怎么停服务？停了数据还在吗？

- 停服务：控制台 `Ctrl+C`（能看到优雅退出日志）
- 停容器：`docker compose stop`（**数据还在**）
- 删容器和数据：`docker compose down -v`（**数据全丢**）

## C. 读代码（9 问）

### C1. 项目文件这么多，从哪开始？

**从 main.go 开始，但只看它调用了谁**，不要陷进细节：

```
main.go
 ├─ core.LoadConfigFile()    → 读配置文件
 ├─ core.InitBaseServices()  → 连 MySQL/Redis/MQ
 ├─ grpcx.StartServers()     → 起 gRPC
 └─ router.NewRouter()       → 注册所有 HTTP 路由  ← 从这里能跳到所有模块
```

跟着 `router.NewRouter()` 就能找到每个模块的入口。

### C2. `internal/` 目录是什么意思？

Go 的特殊约定：**`internal/` 下的包只能被本项目 import**，外部项目无法引用。
作用：把"不想暴露给别人"的代码放进去。

### C3. 为什么包名和目录名不一样？（`usermodel` vs `user_model`）

目录名可以带下划线，但 Go 的包名习惯用**全小写无下划线**（`usermodel`）。
import 时起别名就是为了清晰：

```go
usermodel "gochat/internal/model/user_model"
```

### C4. `global.DB` 是在哪初始化的？我找不到定义怎么办？

三步定位：

1. `global/global.go` 里有一行 `var DB *gorm.DB`
2. 搜索 `global.DB =`（在 `core/db/init_mysql.go` 里赋值）
3. `main.go` 里 `core.InitBaseServices()` 调用了它

> VS Code 里 `Ctrl+点击` 变量名可以直接跳转定义，`Shift+F12` 能看所有引用。

### C5. `model.Model` 里面有什么？

```go
type Model struct {
    gorm.Model    // 展开是：ID / CreatedAt / UpdatedAt / DeletedAt
}
```

- `ID`：自增主键
- `CreatedAt` / `UpdatedAt`：GORM 自动维护时间
- `DeletedAt`：软删除标记，GORM 查询会自动加 `WHERE deleted_at IS NULL`

### C6. `gin.H` 是什么？

```go
type H map[string]any
```

就是 map 的简写别名。`gin.H{"code": 0}` 等价于 `map[string]any{"code": 0}`。用它是为了少打字。

### C7. `ShouldBindJSON` 和 `BindJSON` 有什么区别？

| | `BindJSON` | `ShouldBindJSON` |
|---|---|---|
| 失败时 | 自动写 400 响应 | **只返回 error，不写响应** |
| 适合 | 简单场景 | **需要自定义错误响应（本项目用这个）** |

### C8. 为什么响应里 `code` 和 HTTP 状态码都是 400，不重复吗？

不重复，两个层：

- **HTTP 状态码 400**：给"基础设施"看的（网关、监控、浏览器）
- **body 里的 `code`**：给"业务"看的（前端根据 code 决定弹什么提示）

本项目暂时让两者一致。大项目里 `code` 会是 10001/20002 这种业务码，和 HTTP 码分开。

### C9. 怎么断点调试？

VS Code 装 Go 插件后，在行号左侧点红点 → 按 F5 → 选 "Go"。
需要 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    { "name": "Go", "type": "go", "request": "launch", "mode": "auto", "program": "${workspaceFolder}", "args": ["-db"] }
  ]
}
```

不想配调试也可以 `log.Printf` 打印，初学者更常用。

## D. 概念（6 问）

### D1. 事务到底怎么用？会不会写错？

记住三步：

```go
err := global.DB.Transaction(func(tx *gorm.DB) error {
    if err := tx.Create(&a).Error; err != nil {
        return err          // 返回 error → 自动回滚
    }
    if err := tx.Create(&b).Error; err != nil {
        return err
    }
    return nil              // 返回 nil → 提交
})
```

**唯一要记住的铁律**：回调里**只用 `tx`，不要用 `global.DB`**。用了 `global.DB` 就是独立事务，回滚管不到。

### D2. 代码里先查重了，为什么还要唯一索引？

因为**先查后插有并发窗口**：

```
请求 A: 查 → 不存在
请求 B: 查 → 不存在       ← 两个都通过了
请求 A: 插入成功
请求 B: 插入成功          ← 数据库里出现两个 alice
```

唯一索引是**数据库层面的最后防线**，保证无论如何都插不进第二条。代码查重只是为了给用户友好提示。

### D3. goroutine 和线程到底差多少？

| | 线程 | goroutine |
|---|---|---|
| 初始栈 | 1–8 MB | **2 KB**（可动态增长） |
| 创建成本 | 微秒级，受 OS 限制 | 纳秒级，Go 运行时调度 |
| 数量级 | 几千个就吃紧 | **几十万个都没问题** |

所以 Go 才能"一个连接两个 goroutine"随便开。

### D4. channel 和锁怎么选？

| 场景 | 用什么 |
|---|---|
| 传递数据 / 排队 / 生产者消费者 | **channel** |
| 保护一块共享内存（map、计数、切片） | **锁** |

口诀：**传数据用 channel，护数据用锁。**

### D5. WebSocket 为什么还要心跳？TCP 不是有 keepalive 吗？

TCP keepalive 默认 **2 小时**才探测一次，且不经过应用层，很多中间设备会忽略。
应用层心跳能做到 **秒级**发现连接已死，及时释放资源。

### D6. 前端也要学吗？

**做这个项目不需要**——前端已经写好了，你只需要用浏览器体验。
但如果你想改界面，需要一点 HTML/CSS/JS。面试一般不问前端细节。

## E. 面试与规划（4 问）

### E1. 这个项目够面试用吗？

**作为个人项目够**，但要满足两点：

1. 你能讲清每条链路的**设计和取舍**（不是背代码）
2. 有 2–3 个能深挖的**难点**（双 token、幂等、Outbox、WebSocket 并发）

面试官更在意"你想过什么"，不是"你写了多少功能"。

### E2. 面试官问"你项目有什么难点"怎么答？

用「问题 → 试过什么 → 最终方案 → 效果」四段式：

> 最难的是 WebSocket 连接管理。**问题**是多个 goroutine 要往同一个连接写，而 gorilla 不允许并发写会 panic。
> **试过**加锁，但持锁写 socket 会阻塞其他发送方。
> **最终**改成读写分离：一个 goroutine 只负责写，其他 goroutine 往 channel 塞数据。
> **效果**是并发推送稳定，且慢客户端不会影响别人。

详见 [面试自测 30 题 Q30](/blog/2026/11/14/06-04-面试自测30题含答案/)

### E3. 学完下一步学什么？

| 方向 | 学什么 |
|---|---|
| 深度 | 消息撤回/已读回执/群公告，把项目改得更完整 |
| 工程 | 单元测试覆盖、CI/CD、Docker 部署、监控（Prometheus） |
| 架构 | 分布式锁、缓存一致性、分库分表、链路追踪 |
| 语言 | Go 泛型、`context` 深入、`pprof` 性能分析 |

### E4. 能不能直接抄这个项目去面试？

**能参考，但必须自己跑通 + 改过至少一个功能**。

面试官随便问一句"你这个限流是怎么触发的"、"消息撤回后未读数怎么变"，没动过手的人立刻露馅。

> 抄代码不丢人，抄了不理解才丢人。
