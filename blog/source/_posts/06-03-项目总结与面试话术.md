## 五、面试话术（按这个顺序讲）

### 1. 开场（30 秒）

> "这个项目是一个仿微信的 IM 后端，Go + Gin + GORM + Redis + RabbitMQ + gRPC。
> 我按 8 个里程碑推进：先做认证和好友，再做单聊和 WebSocket，然后群聊、并发加固、WebRTC 语音，
> 最后拆微服务和接消息队列。每个里程碑都有完整的接口和测试。"

### 2. 挑 2–3 个亮点深入（不要全讲）

**亮点 A：双 token 无感刷新（M1）**

> "access token 2 小时、refresh token 30 天。refresh 的 jti 存 Redis 白名单，登出就能撤销。
> 刷新时用 `GETDEL` 原子消费旧 jti，配合 rotation 防止 refresh 被重复使用。
> 如果旧 jti 不存在，判定为盗用，撤销该用户所有 refresh——这就是复用检测。"

**亮点 B：消息幂等（M2）**

> "客户端为每条消息生成 client_msg_id，数据库有 `UNIQUE(sender_id, client_msg_id)`。
> 先查后插，并发插入撞唯一索引时捕获 `gorm.ErrDuplicatedKey` 再查一次返回。
> 这样无论重试多少次，库里只有一条消息。"

**亮点 C：WebSocket 架构（M2）**

> "每个连接一个读 goroutine + 一个写 goroutine，因为 gorilla/websocket 不允许并发写。
> Hub 用 RWMutex 管理 userID → 多连接（支持多端登录）。
> 心跳 ping/pong 清理僵尸连接，慢消费者有界队列满了就断开，避免拖垮推送方。"

**亮点 D：接受好友申请事务（M1）**

> "接受申请要改状态 + 插两条好友关系，必须在一个事务里。
> 用条件更新 `WHERE status=0` + RowsAffected 判断，天然抗并发重复接受。
> 还踩过软删除+唯一索引的坑：删除后再加好友会撞索引，所以用 Unscoped 查旧行然后恢复。"

**亮点 E：Outbox 模式（M7）**

> "落库和发 MQ 无法原子。我在业务事务里同时写一条 outbox 记录，后台 worker 轮询发 MQ、标记已发送。
> 这样 MQ 挂了也不丢消息，消费方做幂等即可。MQ 不可用时降级为同步推送。"

### 3. 被问「难点」怎么答

| 问题 | 答法 |
|---|---|
| 最难的部分 | WebSocket 并发管理（读写分离、慢消费者、心跳）+ 双 token 并发刷新 |
| 踩过的坑 | 软删除+唯一索引冲突、GORM 零值陷阱、事务里误用 global.DB、amqp.Table 不支持 uint |
| 怎么验证的 | 每个接口都写了 curl 端到端脚本，WS 用 .NET ClientWebSocket 实测 |
| 如果重做 | 会话创建加唯一键防并发重复、未读数用 Redis 计数、WebSocket 多实例用 Redis 广播 |

### 4. 主动补充「可改进方向」（体现深度）

- 会话创建并发去重（唯一键 `single_key`）
- 未读数用 Redis 计数器替代 N 次 count
- WebSocket 多实例：Redis Pub/Sub 或 MQ 广播
- 消息已读回执、消息撤回
- 群通话（SFU/MCU）
- 链路追踪（trace_id）、监控指标
- 测试覆盖率（目前主要是端到端脚本）

## 七、怎么读这个项目（学习路径）

1. **先看本文**（了解全貌）
2. **读 `learn/00-学习总览.md`**（路线图 + 阅读方法）
3. **按里程碑读**：`m1` → `m7`，每篇都是「目标 → 设计思路 → 代码导读 → 注意点 → 面试点」
4. **对照代码**：每篇的「代码导读」表里有文件路径
5. **用 `面试集.md` 自测**：72 题，能讲出来才算会
6. **用 `场景集.md` 练表达**：30 个场景，按「问题→方案→关键点」讲
