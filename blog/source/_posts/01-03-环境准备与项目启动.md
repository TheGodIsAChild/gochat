> 目标：搞懂「从一条命令到服务能响应」，这中间发生了什么。
> 读完你能理解 `main.go`、`config.yaml`、`core/` 三者的关系。

## 一、先看项目怎么启动

```
docker compose up -d    # 起 MySQL / Redis / RabbitMQ
go run . -db            # 编译并运行，-db 表示顺便建表
```

`go run .` 会找当前目录的 `package main`，也就是 `main.go`。

## 二、config.yaml：配置为什么单独放文件

```yaml
server:
  addr: ":8080"
mysql:
  host: "127.0.0.1"
  port: 3307
  user: "gochat"
  password: "gochat123"
  database: "gochat"
redis:
  addr: "127.0.0.1:6379"
jwt:
  secret: "gochat-dev-secret-change-me"
  access_expire_minutes: 120
  refresh_expire_hours: 720
grpc:
  user_addr: "127.0.0.1:9001"
  chat_addr: "127.0.0.1:9002"
```

**为什么不硬编码在代码里？**

- 开发/测试/生产环境配置不同，改配置不用改代码
- 密码、密钥不应该进 git（生产用环境变量/配置中心）
- 运维可以直接改配置重启，不用重新编译

## 三、internal/config：配置的 Go 结构体

YAML 是文本，Go 需要结构体来接。`internal/config/mysql_config.go`：

```go
type Mysql struct {
    Host     string `yaml:"host"`
    Port     int    `yaml:"port"`
    User     string `yaml:"user"`
    Password string `yaml:"password"`
    Database string `yaml:"database"`
    Charset  string `yaml:"charset"`
}

// DB_DSN 把结构体拼成 GORM 需要的 DSN 字符串
func (m Mysql) DB_DSN() string {
    return fmt.Sprintf("%s:%s@tcp(%s:%d)/%s?charset=%s&parseTime=True&loc=Local",
        m.User, m.Password, m.Host, m.Port, m.Database, m.Charset)
}
```

**逐行解释**：

- `` `yaml:"host"` `` 是 **struct tag**，告诉 YAML 库：YAML 里的 `host` 对应这个字段
- `DB_DSN()` 是**方法**（值接收者），把配置拼成 DSN
- `parseTime=True`：让 MySQL 的 DATETIME 自动解析成 Go 的 `time.Time`（否则拿到的是字符串）
- `loc=Local`：时区用本地时区

> **注意点**：`type Mysql struct{}` 只放「数据定义」，不放「读取逻辑」——读取逻辑在 `core/` 里。
> 这是用户最初就要求的分工：**定义与读取分离**。

## 四、core/init_config.go：读取配置的三步

```go
// 1. 解析命令行参数
func LoadConfigFile() {
    flag.StringVar(&flagConfig.ConfigPath, "config", "./config.yaml", "配置文件路径")
    flag.BoolVar(&flagConfig.InitDB, "db", false, "是否初始化数据库表")
    flag.Parse()
    global.ConfigPath = &flagConfig.ConfigPath
}
```

**逐行**：

- `flag.StringVar(指针, 参数名, 默认值, 说明)` —— 注意第 3 个参数是**默认值**，不是说明文字（这里踩过坑！）
- `-db` 参数决定要不要执行 AutoMigrate（建表）
- 解析结果存到 `global.ConfigPath`（全局变量）

```go
// 2. 读文件 + 解析 YAML
func LoadConfig() (bool, error) {
    bytes, err := os.ReadFile(*global.ConfigPath)
    if err != nil {
        return false, fmt.Errorf("config 加载失败: %w", err)
    }
    if err := yaml.Unmarshal(bytes, &global.Config); err != nil {
        return false, fmt.Errorf("yaml 配置解析错误: %w", err)
    }
    return true, nil
}
```

**逐行**：

- `os.ReadFile` 把整个文件读成 `[]byte`
- `yaml.Unmarshal(bytes, &global.Config)` —— 第二个参数**必须传指针**，否则解析结果写不进去
- `%w` 是 Go 的错误包装语法，保留原始错误链（`errors.Is` 能判断）

```go
// 3. 初始化各种基础服务
func InitBaseServices() error {
    if _, err := db.LoadMysql(); err != nil {
        return fmt.Errorf("数据库连接失败: %w", err)
    }
    if flagConfig.InitDB {
        if _, err := db.InitMysqlTables(); err != nil {
            return fmt.Errorf("数据库建表失败: %w", err)
        }
    }
    if _, err := db.LoadRedis(); err != nil {
        return fmt.Errorf("初始化 Redis 失败: %w", err)
    }
    if err := mq.LoadMq(); err != nil {
        log.Printf("RabbitMQ 连接失败，消息将使用同步推送: %v", err)   // 可选依赖，失败降级
    }
    return nil
}
```

**逐行**：

- MySQL/Redis 是**必需依赖**：失败就返回 error，main 里 `log.Fatal` 退出
- RabbitMQ 是**可选依赖**：失败只打日志，应用继续跑（消息改为同步推送）——这就是「降级设计」

## 五、db.LoadMysql：GORM 连接数据库

`core/db/init_mysql.go`：

```go
func LoadMysql() (*gorm.DB, error) {
    dsn := global.Config.Mysql.DB_DSN()

    db, err := gorm.Open(mysql.Open(dsn), &gorm.Config{
        DisableForeignKeyConstraintWhenMigrating: true,  // 不生成物理外键
        TranslateError: true,                            // Duplicate 错误翻译成哨兵错误
    })
    if err != nil {
        return db, fmt.Errorf("数据库连接失败: %w", err)
    }

    sqlDB, _ := db.DB()            // 取出底层 *sql.DB
    sqlDB.SetMaxOpenConns(50)      // 最大连接数
    sqlDB.SetMaxIdleConns(10)      // 最大空闲连接
    sqlDB.SetConnMaxLifetime(time.Hour)  // 连接最长存活时间

    global.DB = db                 // 存到全局，供 service 层使用
    return db, nil
}
```

**逐行**：

- `gorm.Open(mysql.Open(dsn), ...)` —— 注意第一个参数是 **`gorm.Dialector`**，不是 dsn 字符串（这里踩过坑）
- `DisableForeignKeyConstraintWhenMigrating`：迁移时不建物理外键，约束交给应用层
- `TranslateError`：MySQL 的 `Duplicate entry` 会变成 `gorm.ErrDuplicatedKey`，业务代码能用 `errors.Is` 判断
- **连接池**：不设置的话默认可能无限开连接，DB 会被打爆

## 六、main.go：把所有东西串起来

```go
func main() {
    core.LoadConfigFile()                                    // 1. 解析参数
    if _, err := core.LoadConfig(); err != nil {             // 2. 读配置
        log.Fatalf("加载配置失败: %v", err)
    }
    if err := core.InitBaseServices(); err != nil {          // 3. 连 DB/Redis/MQ
        log.Fatalf("初始化基础服务失败: %v", err)
    }

    grpcServers, err := grpcx.StartServers(...)              // 4. 起 gRPC 微服务
    grpcx.Dial(...)                                          //    建立客户端连接

    srv := &http.Server{Addr: ..., Handler: router.NewRouter()}  // 5. 起 HTTP
    go srv.ListenAndServe()

    // 6. 等退出信号，优雅关闭
    <-quit
    srv.Shutdown(ctx)
    ws.DefaultHub.CloseAll()
    core.CloseBaseServices()
}
```

**为什么用 `http.Server` 而不是 `r.Run()`？**

`r.Run()` 是阻塞的，进程被 kill 时处理中的请求会被硬切断。
用 `http.Server` + 信号监听，可以做到「停止接收新请求 → 等待处理中的请求完成 → 释放资源」。

## 七、/health：最简单的接口

`internal/router/health/health_api.go`：

```go
func HealthRouter(r *gin.Engine) {
    r.GET("/health", func(c *gin.Context) {
        c.JSON(200, gin.H{"status": "ok"})
    })
}
```

**逐行**：

- `r.GET(路径, handler)` 注册一个 GET 路由
- `c *gin.Context` 是 gin 的请求上下文（拿参数、写响应都用它）
- `gin.H` 就是 `map[string]any` 的简写
- **为什么要有健康检查？** 负载均衡/K8s 用它判断服务是否存活
