> 目标：30 分钟内让项目跑起来，并**看懂启动过程中每一步在做什么**。
> 本文所有配置和日志都来自真实项目，不是示例。

## 一、你需要装什么

| 软件 | 版本 | 检查命令 | 用途 |
|---|---|---|---|
| Go | 1.21+ | `go version` | 编译运行项目 |
| Docker Desktop | 最新 | `docker version` | 跑 MySQL/Redis/RabbitMQ |
| 编辑器 | VS Code + Go 插件 | — | 读代码、断点调试 |
| 浏览器 | Chrome/Edge | — | 体验前端 |

> **不需要在本机安装 MySQL/Redis**——全部用 Docker，卸载干净、不污染环境。

## 二、为什么数据库端口是 3307 而不是 3306

看 `docker-compose.yml` 里 MySQL 的完整定义：

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: gochat-mysql
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: gochat
      MYSQL_USER: gochat
      MYSQL_PASSWORD: gochat123
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
    ports:
      - "3307:3306"       # ← 关键：宿主机 3307 映射到容器 3306
    volumes:
      - gochat_mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-proot"]
      interval: 5s
      timeout: 3s
      retries: 12
```

### 逐项解释

| 配置 | 作用 |
|---|---|
| `image: mysql:8.0` | 用官方 MySQL 8.0 镜像 |
| `container_name` | 固定容器名，方便 `docker exec -it gochat-mysql ...` |
| `MYSQL_*` 环境变量 | 首次启动时自动建库、建用户（**只在数据卷为空时生效**） |
| `--character-set-server=utf8mb4` | 支持中文和 emoji（`utf8` 只有 3 字节，存不了 emoji） |
| `ports: "3307:3306"` | 宿主机 3307 → 容器 3306。**为什么？** 很多开发机 3306 已被本机 MySQL 占用，用 3307 避开冲突 |
| `volumes: gochat_mysql_data` | 数据持久化到 Docker 卷，容器删了数据还在 |
| `healthcheck` | 每 5 秒 ping 一次，`docker ps` 显示 `(healthy)` 才说明真起来了 |

> **注意点**：`MYSQL_*` 只在「数据卷为空」时生效。改了密码但卷还在，新密码不会应用——需要 `docker compose down -v` 删卷重来。

### Redis 和 RabbitMQ

```yaml
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]

  rabbitmq:
    image: rabbitmq:3-management
    environment:
      RABBITMQ_DEFAULT_USER: gochat
      RABBITMQ_DEFAULT_PASS: gochat123
    ports:
      - "5672:5672"      # AMQP 协议（程序连这个）
      - "15672:15672"    # 管理界面（浏览器看这个）
```

**两个端口别搞混**：`5672` 是程序用的 AMQP 端口；`15672` 是 Web 管理界面，浏览器打开 `http://127.0.0.1:15672`，账号 `gochat/gochat123`。

## 三、启动依赖

```bash
cd gochat
docker compose up -d
```

第一次会下载镜像（约 500MB，视网络情况）。等待后检查：

```bash
docker ps
```

三个容器都应为 `Up ... (healthy)`：

```
gochat-mysql       Up 2 minutes (healthy)
gochat-redis       Up 2 minutes (healthy)
gochat-rabbitmq    Up 2 minutes (healthy)
```

**MySQL 一直不是 healthy 怎么办**：

```bash
docker logs gochat-mysql --tail 50
```

常见原因是 3307 端口被占用，或磁盘空间不足。

## 四、配置文件逐行讲

`config.yaml` 全文（30 行）：

```yaml
# gochat 配置文件（开发环境）
server:
  addr: ":8080"
  mode: "debug"        # gin 运行模式：debug / release / test

mysql:
  host: "127.0.0.1"
  port: 3307           # ← 对应 docker-compose 里的宿主机端口
  user: "gochat"
  password: "gochat123"
  database: "gochat"
  charset: "utf8mb4"

redis:
  addr: "127.0.0.1:6379"
  password: ""
  db: 0                # Redis 有 16 个逻辑库，0 是默认

rabbitmq:
  url: "amqp://gochat:gochat123@127.0.0.1:5672/"

jwt:
  secret: "gochat-dev-secret-change-me"
  access_expire_minutes: 120     # access token 有效期 2 小时
  refresh_expire_hours: 720      # refresh token 有效期 30 天

grpc:                            # M6 微服务：gRPC 服务地址
  user_addr: "127.0.0.1:9001"
  chat_addr: "127.0.0.1:9002"
```

### 三个要点

1. **`jwt.secret` 是签名密钥**，绝不能提交到公开仓库（生产用环境变量注入）
2. **`access_expire_minutes: 120`** 想验证无感刷新，把它改成 `1`，1 分钟后 token 过期，观察前端怎么自动续期
3. **`grpc.*_addr`** 是 M6 微服务地址。单进程演示时，服务端和客户端在同一个进程里

## 五、配置是怎么被读进程序的

YAML 是文本，Go 程序需要结构体来接。分两步：

### 第 1 步：定义结构体（`internal/config/`）

```go
type Mysql struct {
    Host     string `yaml:"host"`
    Port     int    `yaml:"port"`
    User     string `yaml:"user"`
    Password string `yaml:"password"`
    Database string `yaml:"database"`
    Charset  string `yaml:"charset"`
}

// 把结构体拼成 GORM 需要的 DSN 字符串
func (m Mysql) DB_DSN() string {
    return fmt.Sprintf("%s:%s@tcp(%s:%d)/%s?charset=%s&parseTime=True&loc=Local",
        m.User, m.Password, m.Host, m.Port, m.Database, m.Charset)
}
```

**`yaml:"host"` 是 struct tag**，告诉 YAML 库：文件里的 `host` 对应这个字段。

**`parseTime=True` 很关键**：不加的话 MySQL 的 `DATETIME` 会以字符串返回，GORM 扫描到 `time.Time` 字段会报错。

### 第 2 步：读文件 + 解析（`core/init_config.go`）

```go
func LoadConfig() (bool, error) {
    bytes, err := os.ReadFile(*global.ConfigPath)
    if err != nil {
        return false, fmt.Errorf("config 加载失败: %w", err)
    }
    if err := yaml.Unmarshal(bytes, &global.Config); err != nil {
        return false, fmt.Errorf("yaml 配置解析错误: %w", err)
    }
    return true, nil
}
```

**逐行说**：

- `os.ReadFile` 把整个文件读成 `[]byte`
- `yaml.Unmarshal(bytes, &global.Config)` —— **第二个参数必须传指针**，否则解析结果写不进原变量（新手最常犯的错）
- `%w` 是 Go 的错误包装语法，保留原始错误链

> **为什么要把「定义」和「读取」分开？**
> 结构体只描述「配置长什么样」；读取逻辑在 `core/` 层。以后改从环境变量/配置中心读，只改 `core/`，结构体不动。

## 六、启动服务并读懂日志

```bash
go run . -db
```

`-db` 表示「顺便建表」（AutoMigrate）。生产环境一般不用。

启动成功的日志：

```
数据库连接成功
[GIN-debug] ... 各种路由注册日志 ...
2026/11/14 12:00:00 gRPC 服务启动: user=127.0.0.1:9001 chat=127.0.0.1:9002
2026/11/14 12:00:00 HTTP 服务启动: :8080
```

| 日志 | 含义 |
|---|---|
| `数据库连接成功` | GORM 连上 MySQL，连接池已建好 |
| `[GIN-debug] GET /api/v1/users/me --> ...` | 每条路由注册成功（debug 模式才打印） |
| `gRPC 服务启动` | M6 的两个微服务在 9001/9002 监听 |
| `HTTP 服务启动: :8080` | 主服务开始接收请求 |

**看到最后一行，才说明真的起来了。**

### 建表是什么时候做的

`-db` 参数触发 `AutoMigrate`：GORM 对比结构体和数据库，**自动补上缺的表和缺的列**。

```go
global.DB.AutoMigrate(
    &usermodel.User{},
    &usermodel.UserSettings{},
    &friendmodel.FriendRequest{},
    // ... 12 张表
)
```

**AutoMigrate 只「加」不「删」**——改字段类型它不会帮你改。所以表结构大改时用 `docker compose down -v` 重建库。

## 七、第一个请求：注册 → 登录 → 访问

### 1. 注册

```bash
curl -X POST http://127.0.0.1:8080/api/v1/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456","nickname":"爱丽丝"}'
```

预期：

```json
{"code":0,"message":"ok","data":{"user_id":1,"username":"alice","nickname":"爱丽丝"}}
```

### 2. 登录，拿双 token

```bash
curl -X POST http://127.0.0.1:8080/api/v1/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456"}'
```

预期（token 已截断）：

```json
{
  "code": 0,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 7200,
    "user": {"id":1,"username":"alice","nickname":"爱丽丝"}
  }
}
```

### 3. 带 token 访问需要登录的接口

```bash
TOKEN="把上一步的 access_token 粘到这里"

curl http://127.0.0.1:8080/api/v1/users/me \
  -H "Authorization: Bearer $TOKEN"
```

### 4. 故意不带 token

```bash
curl -i http://127.0.0.1:8080/api/v1/users/me
```

返回 `401`：

```json
{"code":401,"message":"缺少 Authorization"}
```

**这验证了鉴权中间件在工作。**

## 八、启动失败排查表

| 现象 | 原因 | 解决 |
|---|---|---|
| `dial tcp 127.0.0.1:3307: connect: connection refused` | MySQL 没起来 | `docker ps` 看状态；`docker logs gochat-mysql` |
| `Access denied for user 'gochat'` | 密码不对 / 卷里是旧密码 | `docker compose down -v` 后重新 `up -d` |
| `listen tcp :8080: bind: address already in use` | 8080 被占用 | 改 `server.addr`，或杀掉占用进程 |
| 启动即 panic | 配置没读到（路径错） | 确认在 `gochat/` 目录执行，或用 `-config` 指定路径 |
| 日志停在 `数据库连接成功` 后卡住 | Redis 连不上 | 检查 `docker ps` |
| `RabbitMQ 连接失败，消息将使用同步推送` | MQ 没起来 | **警告不是错误**，功能会降级继续跑 |

最后一条特别说明：**RabbitMQ 是可选依赖**。连不上时程序不退出，而是降级为「同步推送」——这是设计好的降级路径，不是 bug。

## 九、动手练习

1. 把 `server.addr` 改成 `":9090"`，重启，访问 `http://127.0.0.1:9090/health`
2. 去掉 `-db` 参数启动，观察日志有什么不同
3. 把 `jwt.access_expire_minutes` 改成 `1`，登录后等 2 分钟再调 `/users/me`，看返回什么
4. 把 `mysql.port` 改成 `3306`（本机可能没有 MySQL），观察启动报错
