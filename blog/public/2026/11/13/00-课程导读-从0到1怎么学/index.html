课程导读：只会 Go 语法，怎么从 0 到 1 学会这个项目

这是一篇「课程说明书」。花 10 分钟读完，能帮你少走很多弯路。

一、这门课面向谁

如果你满足以下条件，这篇博客就是为你写的：

  • ✅ 会 Go 基本语法（变量、函数、struct、interface、goroutine 的写法见过）
  • ✅ 懂计算机基础（进程/线程、HTTP、数据库是什么、SQL 会写一点）
  • ❌ 没做过完整项目（不知道分层怎么分、项目怎么组织）
  • ❌ 没用过 Gin / GORM / Redis / WebSocket / gRPC / RabbitMQ

不需要你提前会这些框架——文章会从「它是什么、为什么用它」讲起。

二、学完你能得到什么

一个能跑、能讲、能改的完整后端项目：

能力 具体表现
能跑 一条命令启动，浏览器打开就是仿微信界面
能讲 面试时能说清每个模块「解决什么问题、怎么解决、有什么坑」
能改 看懂任意一个文件的代码，能自己加功能（如消息撤回）

三、先建立全局印象

看图先记住三件事：

  1. 客户端只和 Gateway（:8080）说话
  2. 内部服务（user :9001 / chat :9002）用 gRPC 通信
  3. 消息推送是异步的：落库 → outbox → RabbitMQ → 消费者 → WebSocket

现在看不懂没关系，读完 M1–M7 再回来看，会有「哦——原来如此」的感觉。

四、学习路径（重要）

不要从第一行代码开始读！按这个顺序：

第 1 步：先跑起来（1 小时）

  1. 装 Docker，docker compose up -d 起 MySQL/Redis/RabbitMQ
  2. go run . -db 启动，浏览器打开 http://127.0.0.1:8080/
  3. 注册两个账号，互相发消息、建群、打语音

目标：先有「这东西能干嘛」的体感，再研究「它怎么实现的」。

第 2 步：读懂骨架（半天）

按顺序读这 3 篇：

  1. 环境准备与项目启动（逐行）
  2. 一次 HTTP 请求的完整链路（逐行）
  3. 代码地图：每个文件是干什么的

目标：知道项目怎么分层、请求从哪进从哪出。

第 3 步：按里程碑深入（每天一个）

顺序 文章 核心知识点
M1 认证与好友 JWT 双 token、事务、软删除
M2 单聊与 WebSocket 消息幂等、游标分页、长连接
M3 群聊 建群事务、权限模型
M4 并发加固 优雅退出、限流、goroutine
M5 WebRTC 语音 信令、SDP/ICE、P2P
M6 微服务 gRPC、服务拆分
M7 消息队列 Outbox 模式、最终一致性

目标：每个里程碑都能回答「解决什么问题 / 怎么解决 / 有什么坑」。

第 4 步：面试冲刺

  • 面试集 72 题
  • 场景集 30 个
  • 踩坑集

五、读代码的三条铁律

铁律 1：沿「一条请求」走，不要按目录读

不要按 model → service → router 的顺序读。正确做法：

打开一个接口（如注册），从路由出发，跟着参数一路往下走，直到数据落库、响应返回。

这样你能看到「层与层之间怎么传数据」，比按目录读高效 10 倍。

铁律 2：先看「注释里的三种标记」

项目代码里大量使用这三种标记，看到就停下来读：

  • 【思路】 —— 为什么这么设计
  • 【注意点】 —— 容易踩的坑
  • 【面试点】 —— 面试会问什么

铁律 3：每个里程碑回答三个问题

读完后，合上电脑，问自己：

  1. 这步解决什么问题？（不讲代码，讲需求）
  2. 怎么解决的？（讲设计，不逐行背）
  3. 有什么坑？（能说出 2–3 个）

答得出来 = 真懂了；答不出来 = 回去补。

六、你需要准备的环境

工具 版本 用途
Go 1.21+ 运行项目
Docker Desktop 最新 跑 MySQL/Redis/RabbitMQ
编辑器 VS Code + Go 插件 读代码/调试
浏览器 Chrome/Edge 体验前端

数据库等依赖全部用 Docker，不需要在本机安装 MySQL。

七、遇到看不懂怎么办

  1. 先看文章里的图：架构图/流程图往往比代码更容易懂
  2. 用 git log 看演进：每个里程碑一个提交，git show <commit> 能看到这步改了什么
  3. 改坏它：把 access token 有效期改成 1 分钟，观察无感刷新；把超时改小，观察重连——比读十遍都有效
