环境准备与项目启动（逐行讲解）

目标：搞懂「从一条命令到服务能响应」，这中间发生了什么。
读完你能理解 main.go、config.yaml、core/ 三者的关系。

一、先看项目怎么启动

go run . 会找当前目录的 package main，也就是 main.go。

二、config.yaml：配置为什么单独放文件

为什么不硬编码在代码里？

  • 开发/测试/生产环境配置不同，改配置不用改代码
  • 密码、密钥不应该进 git（生产用环境变量/配置中心）
  • 运维可以直接改配置重启，不用重新编译

三、internal/config：配置的 Go 结构体

YAML 是文本，Go 需要结构体来接。internal/config/mysql_config.go：

逐行解释：

  • `yaml:"host"` 是 struct tag，告诉 YAML 库：YAML 里的 host 对应这个字段
  • DB_DSN() 是方法（值接收者），把配置拼成 DSN
  • parseTime=True：让 MySQL 的 DATETIME 自动解析成 Go 的 time.Time（否则拿到的是字符串）
  • loc=Local：时区用本地时区

注意点：type Mysql struct{} 只放「数据定义」，不放「读取逻辑」——读取逻辑在 core/ 里。
这是用户最初就要求的分工：定义与读取分离。

四、core/init_config.go：读取配置的三步

逐行：

  • flag.StringVar(指针, 参数名, 默认值, 说明) —— 注意第 3 个参数是默认值，不是说明文字（这里踩过坑！）
  • -db 参数决定要不要执行 AutoMigrate（建表）
  • 解析结果存到 global.ConfigPath（全局变量）

逐行：

  • os.ReadFile 把整个文件读成 []byte
  • yaml.Unmarshal(bytes, &global.Config) —— 第二个参数必须传指针，否则解析结果写不进去
  • %w 是 Go 的错误包装语法，保留原始错误链（errors.Is 能判断）

逐行：

  • MySQL/Redis 是必需依赖：失败就返回 error，main 里 log.Fatal 退出
  • RabbitMQ 是可选依赖：失败只打日志，应用继续跑（消息改为同步推送）——这就是「降级设计」

五、db.LoadMysql：GORM 连接数据库

core/db/init_mysql.go：

逐行：

  • gorm.Open(mysql.Open(dsn), ...) —— 注意第一个参数是 gorm.Dialector，不是 dsn 字符串（这里踩过坑）
  • DisableForeignKeyConstraintWhenMigrating：迁移时不建物理外键，约束交给应用层
  • TranslateError：MySQL 的 Duplicate entry 会变成 gorm.ErrDuplicatedKey，业务代码能用 errors.Is 判断
  • 连接池：不设置的话默认可能无限开连接，DB 会被打爆

六、main.go：把所有东西串起来

为什么用 http.Server 而不是 r.Run()？

r.Run() 是阻塞的，进程被 kill 时处理中的请求会被硬切断。
用 http.Server + 信号监听，可以做到「停止接收新请求 → 等待处理中的请求完成 → 释放资源」。

七、/health：最简单的接口

internal/router/health/health_api.go：

逐行：

  • r.GET(路径, handler) 注册一个 GET 路由
  • c *gin.Context 是 gin 的请求上下文（拿参数、写响应都用它）
  • gin.H 就是 map[string]any 的简写
  • 为什么要有健康检查？ 负载均衡/K8s 用它判断服务是否存活

八、动手练习

  1. 把 server.addr 改成 :9090，重启，访问 http://127.0.0.1:9090/health
  2. 把 -db 参数去掉，观察启动日志（不再建表，但服务正常）
  3. 故意把 MySQL 密码改错，观察启动报错信息
