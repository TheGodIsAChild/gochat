学习路线图：这个项目该怎么学

上图由项目手绘 SVG 说明，配合下文阅读效果更好。

本目录是 gochat 项目的学习文档中心。代码在 gochat/，文档在 gochat-study/。
阅读顺序：本文 → 各里程碑文档 → 面试集 / 场景集 → 对照代码。

一、项目定位

gochat 是一个「仿微信」的即时通讯后端，用来练并发编程、微服务拆分、消息队列。

技术栈：

层 技术
Web 框架 Gin
ORM GORM + MySQL 8
缓存 Redis
鉴权 JWT 双 token（access + refresh）
实时通信 gorilla/websocket
语音 Pion WebRTC（信令服务）
消息队列 RabbitMQ
微服务 gRPC + protobuf
语言 Go 1.27

二、里程碑路线图

里程碑 内容 状态 文档
M0 项目脚手架、配置加载、/health ✅ —
M1 用户 + 好友：注册/登录/双 token/资料/搜索/好友申请（事务）/黑名单 ✅ m1-认证与好友.md
M2 单聊：会话、消息幂等、WebSocket 长连接、在线状态、离线消息 ✅ m2-单聊与WebSocket.md
M3 群聊：建群事务、拉人/踢人/退群、群资料、解散、群消息复用 ✅ m3-群聊.md
M4 并发加固：优雅退出、滑动窗口限流、WS 关闭、扇出限并发、并发测试 ✅ m4-并发加固.md
M5 语音：WebRTC 信令（offer/answer/ice 转发）、通话状态机、通话记录 ✅ m5-WebRTC语音信令.md
M6 微服务：gRPC 拆分（user / chat 服务）+ HTTP gateway ✅ m6-微服务化-gRPC.md
M7 RabbitMQ：本地消息表 + 异步投递 + 消费推送 + 降级 ✅ m7-RabbitMQ与最终一致性.md

架构节奏：先单体（M0–M5）跑通，再拆微服务（M6）+ 接 MQ（M7）。
这样你能真实体会「单体哪里会痛、为什么要拆」。

四、如何阅读本项目代码

1. 先看目录，建立「分层」直觉

依赖方向：router → service → model/global。单向，不回头。

2. 沿着一个请求走一遍

推荐从「注册」开始追：

再追「登录」，看双 token 怎么签发：

3. 看注释里的「【思路】【注意点】【面试点】」

代码里用这三种标记，直接对应你的学习目标：

  • 【思路】：为什么这么设计
  • 【注意点】：容易踩的坑
  • 【面试点】：面试高频问题

4. 配合 git log 看演进

五、学习建议

  1. 先读文档建立全局，再读代码——别一上来钻细节。
  2. 每个里程碑回答三个问题：这步解决什么问题？怎么解决的？有什么坑？
  3. 重点不是”看懂”，而是”能讲出来”——面试集就是练这个。
  4. 动手改：比如把 access token 有效期改成 1 分钟，观察无感刷新行为。
  5. 关注 M2–M4 的并发部分，那是这个项目区别于普通 CRUD 项目的核心价值。
