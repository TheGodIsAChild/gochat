课程导读：只会 Go 语法，怎么从 0 到 1 学会这个项目

这是一篇学习说明书，不是技术文章。
读完它，你会知道：这个项目做了什么、你要按什么顺序学、每天花多久、怎么判断自己学会了。

一、这个项目到底做了什么

先说结论：一个能跑起来的「仿微信」后端。

具体到你可以在浏览器里做的操作：

  1. 打开 http://127.0.0.1:8080/，注册一个账号
  2. 再开一个无痕窗口，注册第二个账号
  3. 两个账号加好友、发消息（对方窗口秒收，不需要刷新）
  4. 建一个群，拉第三个人进来，在群里聊天
  5. 点击聊天窗口右上角的电话图标，两个窗口之间真的能语音通话
  6. 给某条消息点「撤回」，对方窗口立刻提示「消息已撤回」

二、为什么这个项目值得学

很多教程项目的问题是：只有一个增删改查，学不到真东西。这个项目刻意选了三个「有难度」的方向：

方向 项目里体现在哪 面试会问什么
并发编程 WebSocket 连接管理、读写双泵、扇出推送、优雅退出 goroutine 泄漏、数据竞争、锁粒度
微服务拆分 单体 M0–M5 → M6 拆成 gRPC 服务 + gateway 为什么拆、怎么拆、拆完什么问题
消息队列 Outbox 模式、异步推送、MQ 挂了降级 最终一致性、消息不丢不重

这三个点，正是「会写 CRUD」和「能独立负责一个服务」之间的差距。

三、前置知识自查

在做这个项目之前，你需要会：

能力 必须吗 不会怎么办
Go 基本语法（变量、函数、struct、interface） ✅ 必须 先看 Go by Example 的前 20 节
goroutine / channel / sync 的基本写法 ✅ 必须 看 Go 官方并发教程
HTTP 是什么、GET/POST 的区别 ✅ 必须 看 MDN 的 HTTP 基础
SQL 基本增删改查、WHERE/ORDER BY ✅ 必须 学 1 小时 SQL 就够了
Gin / GORM / Redis / WebSocket / gRPC ❌ 不需要 本项目会从”它是什么”讲起
Docker ⚠️ 会用命令就行 只需要 docker compose up -d 和 docker ps

一句话：会 Go 语法 + 懂 HTTP + 会写 SQL，就可以开始了。

四、整体学习路线（6 个阶段）

这是最重要的部分。不要按文件夹顺序读代码，按下面的阶段走：

阶段 1：先跑起来（第 1 天，约 1 小时）

  • 读：环境准备与项目启动
  • 做：起 Docker → go run . -db → 浏览器注册/登录/发消息
  • 验证：能看到登录页、能收到另一个窗口的消息

为什么第一步不是读代码？因为你连「这东西能干嘛」都不知道的时候，读代码是纯抽象。

阶段 2：搞懂骨架（第 2–3 天）

  • 读：一次 HTTP 请求的完整链路
  • 读：代码地图
  • 验证：合上电脑，能在纸上画出「handler → service → model → DB」四层，并说出每层职责

阶段 3：按里程碑深入（第 4–12 天，每天一个）

顺序 读什么 核心问题
M1 认证与好友 双 token 为什么能无感刷新？好友为什么存两行？
M2 实时消息与 WebSocket 消息怎么防重复？长连接怎么管？
M3 群聊 建群为什么要事务？人数怎么统计？
M4 并发加固 为什么锁里不能做 IO？怎么优雅退出？
M5 WebRTC 语音 服务器为什么只转发不传音视频？
M6/M7 微服务与消息队列 怎么拆？拆完多了哪些问题？消息怎么不丢？

验证方式：每读完一个里程碑，用「三个问题」自测（见第七节）。

阶段 4：读关键源码（第 13–16 天）

  • 先读 源码走读总索引，按推荐顺序读
  • 重点文件：main.go → middleware/auth.go → user_service/register_service.go → ws/hub.go → ws/client.go

验证方式：能不看注释，说出某个函数每一行在干什么。

阶段 5：动手改一个功能（第 17–19 天）

推荐做消息撤回：

  • 读：接到需求怎么动手（就是一个完整例子）
  • 自己做一遍：加接口、改 service、前端加按钮

验证方式：能用 curl 走通「发消息 → 撤回 → 重复撤回报错 → 撤回别人的消息报错」。

阶段 6：面试准备（第 20–21 天）

  • 面试集 72 题
  • 场景集 30 个
  • 项目总结与面试话术

验证方式：能对着白板讲 5 分钟这个项目，并接住 3 个追问。

五、每天怎么学（3 周计划）

周 每天 1.5 小时 周末
第 1 周 阶段 1 + 2 + M1/M2 补前面的坑 + 把项目跑通两遍
第 2 周 M3–M7 读源码 + 画出架构图
第 3 周 改功能 + 面试题 模拟面试 + 整理笔记

不要追求「看完」。追求「能讲出来」。 看完 10 篇讲不出来，不如精读 3 篇能讲清。

六、读代码的三遍法（非常关键）

第一遍：只看结构（10 分钟）

不要看函数体，只看：

  • 这个文件有哪些函数？（函数名就说明了职责）
  • 它 import 了什么？（能看出依赖方向）
  • 有没有 // 【思路】 这类注释？（先读注释）

第二遍：跟一条链路（30 分钟）

打开一个接口（比如注册），从 URL 一路跟到数据库：

只跟一条，别的都跳过。跟完你就懂了这一层的协作方式。

第三遍：改坏它（20 分钟）

这是最有效的一遍：

  • 把 access_expire_minutes 改成 1，观察 token 怎么过期、前端怎么无感刷新
  • 把消息的 client_msg_id 去掉，观察重复发送会怎样
  • 把 Auth() 中间件从路由组里去掉，观察接口变成了什么

改坏 → 看现象 → 想原因 → 改回来。这一轮下来，比读十遍都记得牢。

七、卡住了怎么办

  1. 看错误信息的第一行，不是堆栈的后半段
  2. 定位到文件和行号，打开那行前后 20 行
  3. 查「踩坑集」：24 个真实坑 里大概率有
  4. 打印关键变量：log.Printf("values: %+v", x)，看数据对不对
  5. 二分法：注释掉一半代码，看问题是否消失

八、学完自检清单

能流畅回答下面 10 个问题，说明你真学会了：

    1. 一个 HTTP 请求从进来到返回，经过了哪几层？每层做什么？
    1. 为什么需要 access token + refresh token 两个？
    1. 消息重复发送怎么防？（说出至少两种手段）
    1. WebSocket 为什么必须读写分离？
    1. 心跳解决什么问题？为什么 ping 间隔要小于超时时间？
    1. 接受好友申请为什么必须用事务？
    1. 群人数为什么冗余存 member_count？
    1. 为什么锁里不能做 IO？
    1. 为什么要拆微服务？拆完多了哪些问题？
    1. MQ 挂了，发消息功能还能用吗？为什么？
